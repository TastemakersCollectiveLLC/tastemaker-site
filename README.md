# Tastemakers Collective Site

Static site: one real HTML page per route, generated by a small Node build
from one CONFIG object, served by Vercel with clean URLs. `card/` is a
standalone contact page that the printed business card QR codes point to.

## Files
- `config.js`: the CONFIG object, every editable string on the site, plus the form endpoint and the empty analytics constants. Loads in the browser as `window.TMC` and in Node as a module.
- `build/build.js` and `build/templates.js`: the build. `node build/build.js` writes every page, the hashed assets, the sitemap, robots, llms.txt and 404.html, then checks them and fails on any problem.
- `index.html`, `weddings.html`, `corporate.html`, `events.html`, `vending.html`, `order.html`, `menus.html`, `about.html`, `contact.html`, `reviews.html`, `404.html`: built pages. Do not edit by hand; the build overwrites them.
- `styles.css`: complete design system and all page styles
- `script.js`: enhancement only. Phone menu, form submit, contact prefill, sticky bar, motion. Every page is complete without it.
- `styles.<hash>.css`, `script.<hash>.js`, `config.<hash>.js`: content-hashed copies the pages reference, written by the build, cached for a year.
- `card/index.html`: standalone contact page at `/card`, self contained with its own inline CSS
- `card/tastemakers.vcf`: vCard the Save contact button downloads
- `robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`: written by the build
- `vercel.json`: `cleanUrls`, `trailingSlash: false`, and the cache headers
- `apps-script/`: the Google Apps Script form backend, versioned here, not served

## Editing content

Everything editable lives in the `CONFIG` object in `config.js`: business
details, the nav, the trust strip, per-page h1s and meta descriptions,
page heroes, the menus, the service and process lists, the closing CTA
headlines and the footer. Change copy there, run `node build/build.js`,
and commit the output with the change. Colors and fonts are CSS custom
properties at the top of `styles.css`.

Slots for Danny's service page paragraphs are `CONFIG.pageCopy`; an empty
slot renders nothing.

## Deploy

1. Run the build and commit everything it changed, to the root of the GitHub repo at `github.com/TastemakersCollectiveLLC/tastemaker-site`.
2. Vercel is already connected, so it auto-deploys on push, usually within a minute. There is no Vercel build step; the built files are what deploys.
3. Domains `tastemakerscollective.us` and `www.tastemakerscollective.us` are already attached, with DNS at Namecheap and SSL issued by Vercel.

## URLs

Pages are `/`, `/weddings`, `/corporate`, `/events`, `/vending`, `/order`,
`/menus`, `/about`, `/contact` and `/card`. `/reviews` exists but is
noindex, unlinked and its form is disabled until the reviews handler is
published. Vercel's `cleanUrls` serves `weddings.html` at `/weddings` and
redirects `/weddings.html` and `/weddings/` to it. Unknown paths get
`404.html`.

Old hash links (`/#/weddings`, `/#/contact?type=wedding`) are forwarded by
a small inline script in every page head. The four retired routes still
forward: `#/inquire` to `/contact`, `#/menu-catering` to `/events`,
`#/menu-vending` to `/vending`, `#/menu-private-chef` to `/contact`.

## Forms

Contact and Order both post to the Google Apps Script web app in
`apps-script/` through one shared submit function, as JSON with a plain
`fetch`. Each form carries its own hidden `form_source`. The submit button
disables while sending. On success the form is replaced with a
confirmation. On failure the form is kept, the button is re-enabled, and
an error offers `hello@tastemakerscollective.us` plus a mailto prefilled
from the answers already typed in.

To add a form, give it `class="tmc-form"`, its own hidden `form_source`, a
field named `email`, a `p.tmc-form-status` and a submit button. The backend
creates its tab on first use.

## Measurement

`GA4_ID` and `META_PIXEL_ID` in `config.js` are empty. While they are empty
nothing loads and every tracking call is a no-op. Fill one in and rebuild to
switch it on.
